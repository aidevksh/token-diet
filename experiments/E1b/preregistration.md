# E1b 사전 등록: 환경과 문제 가르기

- 작성: 2026-10-11, 본 실행 전. 이 문서와 분석 코드(`scripts/analyze_e1b.py`)를 커밋한 뒤 실행한다. 결과를 본 뒤에는 바꾸지 않는다.
- 실행 규칙: `CLAUDE.md`의 "논문 트랙 실행 규칙"

## 배경

E1에서 u01n(구조 사전 맥락 + 지시 문장)의 이득이 재현되지 않았다. R6 호스트에서는 생성기 문제에서 n09 대비 −13%였는데, E1 컨테이너에서는 −0.5%였다. 규칙 수정과 명세 구현에서 이득이 사라졌다.

E1과 R6는 두 가지가 동시에 달랐다.
- **문제 seed**: R6는 13~28, E1은 29~52다.
- **실행 환경**: R6는 macOS 호스트, E1은 Linux 컨테이너다.

탐색 분석에서 실행 환경의 차이 두 가지가 드러났다.
1. **경로 길이**: 호스트 n09의 명령 속 절대 경로는 평균 110자였고, 컨테이너는 13자(`/work`)였다.
2. **scratchpad 안내**: 호스트 CLI는 시스템 프롬프트에 "임시 파일은 scratchpad에 두라"는 문구와 긴 경로를 넣는다. 컨테이너 CLI에서는 이 기능이 꺼져 있다.
   - 호스트 n09의 경로 문자 중 3분의 2가 scratchpad 경로였다(실행당 200자, 작업 폴더 경로는 101자).
   - 이 안내가 "스크립트를 파일로 쓰고 따로 실행하는" 작업 방식을 늘렸을 수 있다.

## 질문과 가설

| ID | 질문 | 비교 |
|---|---|---|
| V1 | 같은 문제(R6)에서 호스트의 u01n 이득이 컨테이너 기본(S)보다 컸는가. 컸다면 환경이, 같다면 문제가 E1의 결과를 설명한다 | D1 |
| V2 | 긴 작업 폴더 경로(L), scratchpad 안내(P), 둘 다(LP)가 u01n의 이득을 키우는가. n09의 출력을 늘리는가 | D_L, D_P, D_LP |
| V3 | 호스트형 환경(LP)이 호스트의 n09 출력 수준을 재현하는가 | 부 비교 |

## 조건 (12개, 한 배치에서 무작위로 섞는다)

| 묶음 | 환경 | 조건 |
|---|---|---|
| S | 컨테이너 기본(E1과 같음): `/work`, scratchpad 안내 없음 | `baseline`, `p1_placebo`, `p2_concise`, `n09_p2_h05`, `u01n_noval`, `e1_content` |
| L | 긴 작업 폴더 경로 | `e1b_n09_L`, `e1b_u01n_L` |
| P | scratchpad 안내 | `e1b_n09_P`, `e1b_u01n_P` |
| LP | 긴 경로 + scratchpad 안내 | `e1b_n09_LP`, `e1b_u01n_LP` |

- `e1b_*` 조건의 CLAUDE.md와 사전 맥락은 원래 조건(n09, u01n)과 같다. 표시 파일(`longpath`, `scratchpad`)만 다르다.
- **긴 경로**: `/private/tmp/claude-501/td-runs/round9/<10자>/<태스크>/r<n>`. 호스트 R6와 같은 형태이고 길이도 65자로 같다. 조건 이름 자리에는 같은 길이의 무의미한 문자열을 넣어, 모델이 조건 이름을 보지 않게 한다.
- **scratchpad 안내**: 호스트 CLI 2.1.296의 원문을 `--append-system-prompt`로 덧붙인다. 경로는 호스트와 같은 형태(`/private/tmp/claude-501/<작업 폴더를 바꾼 이름>/<세션 ID>/scratchpad`)로 만든다. 세션 ID는 `--session-id`로 고정하고, 디렉터리는 미리 만든다.
  - 호스트에서는 이 문구가 시스템 프롬프트의 환경 정보 부분에 들어간다. 여기서는 끝에 붙는다. 이 위치 차이는 한계로 남긴다.

- **문제**: `tasks_gen3`, 생성기 L5 규칙 수정·매출 분석·배송비 명세 구현 각 16개(seed 13~28), 합계 48개. R6 호스트 실행(`results/runs_r9.jsonl`, 2026-10-10)과 같은 문제다.
- **규모**: 12조건 × 48문제 × 1회 = **576회**. 순서는 `--seed 11`, 동시 실행은 4개다.
- **환경**:

  | 항목 | 값 |
  |---|---|
  | 이미지 | `token-diet:2.1.296` (image ID `sha256:b526c52b6e5b`). E1 이미지와 Claude Code가 같고, 진입 스크립트에 작업 폴더 지정과 scratchpad 디렉터리 생성만 더했다 |
  | 모델 | Opus 5.5 high |

- **실행 명령**: `python scripts/drive.py experiments/E1b/plan.json`

## 분석 (`scripts/analyze_e1b.py`, 이 커밋에 고정)

| ID | 정의 | 음수의 뜻 |
|---|---|---|
| D1 | 문제마다 [log(u01n/n09)_호스트R6 − log(u01n/n09)_S]의 평균 | 호스트에서 u01n의 이득이 더 컸다 |
| D_X (X = L, P, LP) | 문제마다 [log(u01n/n09)_X − log(u01n/n09)_S]의 평균 | X 환경에서 u01n의 이득이 더 컸다 |

- **CI와 p값**: 문제를 재표집하는 부트스트랩 4000회로 95% CI와 양측 p를 낸다. 주 비교 네 개(D1, D_L, D_P, D_LP)에는 Holm 보정을 한다.
- **"유의" 판정**: CI 상한 < 0이고 Holm p < 0.05일 때다.
- **부 비교** (보정 없음):
  - 각 묶음의 u01n 대 n09
  - n09와 u01n 각각의 묶음 간 비교(X 대 S)
  - 호스트 대 S, 호스트 대 LP
  - 사전 맥락만 대 n09(S)
  - 대조군 대 베이스라인
  - 생성기별 결과
- **판정**: 코드의 `verdicts`(V1, V2, V3)를 그대로 쓴다.
- **품질**: E1과 같다(거짓 성공 거부권, 점수·Q4 비열등성 δ = 0.05, 베이스라인은 S 묶음).
- **메커니즘**: 턴, 도구 호출 수, 명령 속 경로 문자 수, scratchpad를 쓴 실행 수를 기술 통계로 보고한다.

## 표본 크기와 한계

- **검정력**: 문제 48개다. 차이의 차이(D) 추정은 분산이 두 배라 95% CI 반폭이 약 ±7~9%다. 12% 이상의 차이를 잡을 수 있다. E1에서 규칙 수정의 변화는 약 20%p(−17% → +5.6%)였다.
- **호스트 비교 (D1, V3)의 한계**:
  - **날짜**: 호스트 데이터는 전날(2026-10-10) 실행이라, 서버 쪽 변화가 섞일 수 있다.
  - **플랫폼**: macOS와 Linux의 차이는 재현하지 못한다.
- **scratchpad 문구의 위치**: 호스트와 다르다(위 조건 설명).
