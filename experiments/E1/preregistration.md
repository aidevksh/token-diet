- 작성: 2026-10-11 08:50 KST, 본 실행 전. 이 문서와 분석 코드(`scripts/analyze_e1.py`)를 커밋한 뒤 실행한다. 결과를 본 뒤에는 바꾸지 않는다.
- 실행 규칙: `CLAUDE.md`의 "논문 트랙 실행 규칙"

## 배경

R5·R6에서 u01(사전 맥락 적재)은 탐색이 많은 생성기 문제에서 n09보다 출력 토큰을 8~13% 더 줄였다(`report/u01_사전맥락.html`). 그런데 u01의 CLAUDE.md에는 사전 맥락과 함께 지시 문장이 들어 있다. "작업 폴더의 파일 목록, 파일 내용, DB 구조는 아래 스냅숏에 이미 있다. 다시 열어 보지 않고 바로 작업한다." 그래서 효과의 원인을 세 가지 중에서 가릴 수 없다.

- 사전 맥락의 내용
- 탐색을 막는 지시 문장
- 단순히 맥락이 길어진 것

- **구조 스냅숏** (`u01n_noval/prerun.py`, `e1_content/prerun.py`는 같은 파일): 작업 폴더의 `ls -la`, 64KB 이하 텍스트 파일 전문, SQLite 스키마와 행 수. 표본 행과 고유값은 넣지 않는다.
- **무관한 문서** (`e1_placebo_ctx/prerun.py`): 가상의 사내 도서관 소장 목록이다.
  - 길이는 같은 작업 폴더에 구조 스냅숏을 만들어 잰 바이트 길이와 같다(한글 경계 때문에 ±1바이트).
  - 내용은 태스크 이름을 seed로 정해서 같은 문제에는 항상 같은 문서가 들어간다.
- `e1_forbid`의 문장은 u01n 지시 문장의 행동 부분("다시 열어 보지 않고 바로 작업한다")을 사전 맥락 없이도 거짓이 되지 않게 고친 것이다. 사전 맥락이 없으므로 "이미 있다"는 문장은 넣지 않았다.

## 분석 (`scripts/analyze_e1.py`, 이 커밋에 고정)

| ID | 비교 | 질문 |
|---|---|---|
| C1 | u01n 대 n09 | 재현 |
| C2 | e1_content 대 n09 | 내용만 |
| C3 | e1_forbid 대 n09 | 금지만 |
| C4 | e1_placebo_ctx 대 n09 | 길이만 |
| C5 | u01n 대 e1_content | 지시 문장의 추가 효과 |
| C6 | e1_content 대 e1_placebo_ctx | 관련성 |

- **효과**: 같은 문제끼리 짝지은 log(조건/기준) 평균, 즉 기하평균 비율이다.
- **CI와 p값**: 문제를 재표집하는 부트스트랩 4000회로 95% CI를 구하고, 양측 p값을 낸다.
- **다중 비교**: 주 비교 C1~C4에는 Holm 보정을 한다. C5·C6는 보정하지 않는다.
- **"줄어듦" 판정**: CI 상한 < 0이고, Holm 보정 p < 0.05(C1~C4)일 때다.
- **품질 기준**: 아래를 모두 만족해야 한다.
  - 거짓 성공 수 ≤ 베이스라인
  - API 거부 0건
  - 베이스라인 대비 점수 차이의 단측 95% 하한 > −0.05
  - Q4 차이의 단측 95% 하한 > −0.05
- 판정 문장은 코드의 `verdicts`를 그대로 쓴다. 생성기별 결과와 메커니즘 지표는 기술 통계로만 보고하고, 판정에 쓰지 않는다.

## 표본 크기 근거

R6에서 같은 처치를 두 번 돌렸을 때 문제별 log 비율의 표준편차가 0.16~0.24였다. 문제 72개면 95% CI 반폭이 약 ±4~6%다.
- **잡을 수 있는 효과**: 8~10% 이상, 검정력 80%
- **놓칠 수 있는 효과**: 5% 이하. C5(지시 문장의 추가 효과)처럼 작을 것으로 예상되는 효과다.
- 그래서 "확인되지 않음"은 효과가 없다는 증거가 아니다.

## 제외·중단·변경 규칙

- **유효하지 않은 실행**: 기록된 모델이 다른 실행은 토큰 분석에서 뺀다. API 거부는 품질에서 0점으로 센다.
- **하네스 오류**: 결과 이벤트가 없는 실행은 드라이버가 다시 돌린다. 횟수는 `log.md`에 적는다.
- **중단**: 5시간 한도 사용률이 85% 이상이면 초기화까지 기다린다. 주간 사용률이 90% 이상이면 멈춘다.
- **계획 변경**: 실행 중에 계획을 바꾸면 `log.md`에 이유와 함께 적고, 결과 해석에서 밝힌다.
- **사전 시험**: 본 실행 전에 이전 라운드 문제(`tasks_v9`)에서 새 조건 세 개를 각 1회 돌려 작동만 확인했다(`results/e1_smoke/runs.jsonl`). 분석에는 넣지 않는다.
