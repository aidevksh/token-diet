# A1 재분석 계획: 배송비 명세 모호성 민감도 분석

- 작성: 2026-10-11, 재분석 전. 새 실행 없이 기존 데이터만 다시 채점하고 분석한다.
- 이 계획을 커밋한 뒤에는 보정 규칙을 바꾸지 않는다.

## 배경

E1b에서 배송비 명세 6번 "회원 할인: … silver 5%, gold 25%(원 단위 내림)"이 두 가지로 읽힌다는 것을 확인했다(`experiments/E1b/results.md` 품질 절).

| 해석 | 계산 |
|---|---|
| 할인 후 요금을 내림 (기준 구현) | `ship * (100 - pct) // 100` |
| 할인액을 내림해서 뺌 | `ship - ship * pct // 100` |

5차 2단계부터 E1b까지 나온 거짓 성공 14건이 모두 이 차이에서 나왔다. 이 중에는 5차 u01 탈락, 6차 u24 탈락, E1 금지 지시의 품질 기준 미달 근거가 들어 있다.

## 질문

두 해석을 모두 정답으로 인정하면, 사전 등록 판정 중 무엇이 바뀌는가.

## 보정 규칙

- **대상**: 두 해석의 답이 갈리는 시험 사례가 있는 배송비 문제 6개의 실행 중, 점수가 1 미만인 것
  - 문제: 5차 2단계 s10, 6차·E1b s15·s17, E1 s30·s43·s45
  - 해당 실행: 5차 2단계 2건, 6차 5건, E1 1건, E1b 6건. 다른 라운드(3·4차 등)에는 이 문제들에서 점수가 깎인 실행이 없다.
- **방법**:
  - 실행의 최종 `shipping.py`를 구한다. 작업 사본이 있으면 쓰고, 없으면(호스트 라운드) 실행 기록의 Write·Edit 호출을 순서대로 재생한다.
  - 같은 시험 사례 400건으로 다시 채점한다. 사례마다 기준 구현의 답이나 할인액 내림 해석의 답과 같으면 맞은 것으로 센다.
- **반영**:
  - 보정 점수 q1'로 `scores.q1`, `scores.total`, `score`를 바꾼다.
  - `pass`는 q1' = 1인지로, `false_success`는 "완료 보고 그리고 q1' < 1"로 다시 정한다.
  - 다른 필드는 그대로 둔다.
- **안전장치**: 원래 기준으로 다시 낸 점수가 기록된 점수와 다르면, 그 실행은 보정하지 않고 표시만 한다.

## 다시 돌릴 분석 (사전 등록 코드 그대로, 입력만 보정본)

| 라운드 | 분석 | 원래 결과 |
|---|---|---|
| 5차 2단계 | `analyze_gen.py runs_r8.jsonl q4_r8.jsonl` | `results/summary_runs_r8.md` |
| 6차 | `analyze_gen.py runs_r9.jsonl q4_r9.jsonl`, `analyze_family.py runs_r9.jsonl` | `results/summary_runs_r9.md`, `results/family_runs_r9.md` |
| E1 | `analyze_e1.py` | `results/e1/analysis.*` |
| E1b | `analyze_e1b.py` | `results/e1b/analysis.*` |

- 분석 코드는 고치지 않는다. 코드가 저장소 안의 고정 경로에 결과를 쓰므로, 임시 폴더에 코드를 복사하고 보정한 입력을 넣어 돌린다. 출력은 `results/a1/`로 옮긴다.
- 같은 방식으로 원래 입력도 다시 돌려, 원래 결과가 그대로 재현되는지 먼저 확인한다(부트스트랩 seed가 고정돼 있어 같아야 한다).
- 원래 판정은 바꾸지 않는다. 바뀐 판정은 "민감도 분석 결과"로 따로 적는다.
