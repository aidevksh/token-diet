- 작성: 2026-10-11, 본 실행 전. 이 문서와 분석 코드(`scripts/analyze_e2.py`)를 커밋한 뒤 실행한다. 결과를 본 뒤에는 바꾸지 않는다.
- 실행 규칙: `CLAUDE.md`의 "논문 트랙 실행 규칙"

## 배경

- 지금까지 모든 라운드는 effort high로 돌렸다.
- Opus 5.5의 기본 effort는 medium이다. Anthropic 문서("Prompting Claude Opus 5.5")는 "thinking을 줄이려면 effort를 먼저 낮춰라. 프롬프트 지시보다 안정적이다"라고 권한다.
- 그래서 논문의 주장("지시로 출력 토큰을 줄이면서 정확도를 유지한다")에는 effort와의 비교가 빠져 있다. 심사에서 가장 먼저 나올 질문이다(`paper/related_work.md`).
- effort를 낮추면 정확도가 떨어질 수 있다. 그래서 정확도 천장 문제에서도 품질 지표가 실제 하락을 잡는지 볼 수 있다. 사전 시험에서 low 베이스라인이 배송비 문제 하나에서 0.845점을 받았다.

## 조건 (15칸, 한 묶음에서 무작위로 섞는다)

| 조건 | high | medium | low |
|---|---|---|---|
| 베이스라인 | `baseline` | `e2_base_med` | `e2_base_low` |
| P1 위약 | `p1_placebo` | `e2_p1_med` | `e2_p1_low` |
| P2 간결 | `p2_concise` | `e2_p2_med` | `e2_p2_low` |
| n09 | `n09_p2_h05` | `e2_n09_med` | `e2_n09_low` |
| 사전 맥락만 (n09 위) | `e1_content` | `e2_ctx_med` | `e2_ctx_low` |

- medium·low 조건 폴더는 원래 조건을 그대로 복사하고 `effort` 파일만 더했다.
- 하네스(`scripts/run.py`)는 이 파일이 있으면 그 값을 `--effort`로 넘기고 결과에 기록한다. 없으면 `TD_EFFORT`(high)를 쓴다.
- `effort` 파일은 컨테이너의 `/in/cond`(읽기 전용)에서 보인다. 작업 폴더에는 복사되지 않는다. E1b의 표시 파일과 같다.

## 분석 (`scripts/analyze_e2.py`, 이 커밋에 고정)

- **단위, CI, p**: 문제마다 log 비율을 구한다. 문제를 재표집하는 부트스트랩 4000회로 95% CI와 양측 p를 낸다.
- **주 비교 7개 (Holm 보정)**:

  | ID | 정의 (문제마다 평균) |
  |---|---|
  | A_e (e = high, medium, low) | log(n09_e / 베이스라인_e) |
  | B_e (e = medium, low) | log(베이스라인_e / 베이스라인_high) |
  | C_e (e = medium, low) | log(n09_e / 베이스라인_e) − log(n09_high / 베이스라인_high) |

- **"유의"**: Holm p < 0.05이고 CI가 0을 포함하지 않을 때다.
- **부 비교 (보정 없음)**:
  - D_e: 사전 맥락만 대 n09 (effort별)
  - E: P1·P2 대 베이스라인 (effort별)
  - F_e: n09(high) 대 베이스라인(e). 지시와 effort 중 무엇이 더 줄이는가
  - G: 합친 감소. n09(medium)·n09(low)·사전 맥락만(low) 대 베이스라인(high)
  - H_e: n09 안에서 effort를 낮춘 효과
  - 생성기별 결과
  - 칸별 메커니즘: 출력, thinking, 보이는 출력, 턴, 도구 호출, 비용, 시간
  - 묶음 간 변동: E2 high 대 E1, 같은 48문제
- **품질**:
  - 점수: 배송비 문제는 A1 규칙으로 두 해석을 모두 정답으로 인정한다. 이 문제 집합에서 해당 문제는 s30, s43이다. 원래 기준 점수도 함께 보고한다.
  - 기준은 두 개다. 같은 effort의 베이스라인, 그리고 high 베이스라인.
  - 품질 기준: API 거부 0, 거짓 성공 ≤ 기준, 점수 차이의 단측 95% 하한 > −0.05, Q4 차이의 하한 > −0.05
- **판정**: 코드의 `verdicts` 그대로 쓴다.

  | 판정 | 내용 |
  |---|---|
  | V1 | effort medium·low에서 n09가 줄이는가, 그리고 같은 effort의 베이스라인 대비 품질 기준을 지키는가 |
  | V2 | effort를 낮추면 출력이 주는가, 그리고 high 베이스라인 대비 품질 기준을 지키는가 |
  | V3 | 상호작용의 방향. 상대 감소가 커지는가, 작아지는가(일부 겹침), 근거가 없는가 |
  | V4 | 지시(n09 high) 대 effort(베이스라인 medium·low) |
  | V5 | high 베이스라인 대비 품질 기준을 지키면서 출력이 가장 적은 칸 |

## 표본 크기와 검정력

- 문제 48개, 칸당 1회다. E1b에서 같은 크기의 짝 비교 95% CI 반폭은 약 ±4~5%였고, 차이의 차이는 약 ±6~9%였다.
- 지시 효과(약 −40%)와 effort 효과는 충분히 잡는다. 상호작용(C)은 약 10% 이상의 차이를 잡을 수 있다.
- 품질 비열등성: high 칸은 정확도가 천장 근처라 검정력이 낮다. low에서 하락이 나오면 잡을 수 있다.

## 제외·중단·변경 규칙

E1·E1b와 같다.
- 유효하지 않은 실행은 토큰 분석에서 뺀다.
- API 거부는 품질 0점으로 센다.
- 5시간 한도 85%에서 기다리고, 주간 90%에서 멈춘다.
- 변경은 `log.md`에 기록한다.

추가 규칙: 기록된 effort가 조건과 다르면 토큰 분석에서 뺀다.
