CLAUDE.md 세 줄로 출력 토큰 40% 감소 가설 55개, 에이전트 실행 1,380회. 측정한 품질 지표는 그대로였다.

Claude Code가 일할 때 내는 출력 토큰(응답, thinking, 도구 호출 인자)을 품질을 해치지 않고 얼마나 줄일 수 있는지 실험했다. 결과적으로 남은 것은 짧은 지시 세 줄이다. 간결하게 답하고, 첫 해법을 채택하고, 검증은 마지막에 한 번만 한다.

실험 목표

품질은 유지하고 출력 토큰만 줄인다

품질 제약이 없으면 "아무것도 하지 않기"가 최고 점수가 된다. 그래서 모든 판정은 출력 감소와 품질 유지를 함께 만족해야 통과한다.

도구 호출 인자

Write, Edit, Bash에 넘기는 내용

tool_use 블록으로 측정한다. 눈에 보이는 출력의 약 95%를 차지한다.

thinking

내부 추론

로그에 본문이 남지 않는다. 블록 834개 중 저장된 본문은 996자였지만 토큰은 그대로 과금된다. thinkingTokens로 잰다.

응답 텍스트

사용자에게 보이는 답변

텍스트 블록으로 측정한다. 실제로는 전체의 약 5%뿐이라, 문체를 압축해도 효과가 작다.

사전 관찰: 눈에 보이는 출력은 대부분 파일 쓰기다

기존 실사용 로그 40개 세션, 문자 수 기준 (thinking 제외)
도구 호출 인자 응답 텍스트

Bash heredoc(cat > file <<EOF)과 Write를 더하면 보이는 출력의 약 60%가 파일 전체 쓰기다. 그래서 처음에는 도구 호출을 겨냥한 가설의 우선순위를 높게 잡았다. 결과는 반대였다(아래 결과 참고).

지표

무엇을 재는가

  • 주 지표: 출력 토큰. modelUsage["claude-opus-5-5"].outputTokens
  • 효과: 문제별 (조건 / 베이스라인) 비율의 기하평균. 큰 태스크가 결과를 좌우하지 않게 한다. 95% CI는 부트스트랩.
  • 품질: R1·R2는 숨은 테스트 통과율. R3부터 Q1 정확도, Q3 거짓 성공, Q4 보고 충분성, Q5 변경 최소성.
  • 보조: 총비용, 턴 수, 소요 시간, 5시간·주간 한도 사용률.
판정 (scripts/analyze.py에 사전 고정)

채택 조건

  • 베이스라인 대비 10% 이상 감소, CI 상한 < 0%
  • 위약(P1) 대비 CI 상한 < 0%
  • 품질 유지: 비열등성 검정, 허용 폭 δ = 0.05 (R3부터)
  • 거짓 성공은 거부권 지표: +2%p 이상이면 탈락
  • 1단계(문제 12개) 선별 후 2단계(새 문제 24개)를 통과해야 채택
과정

네 라운드 동안 측정 방법을 계속 고쳤다

라운드마다 앞 라운드의 약점을 고쳤다. R1에는 위약이 없었고, R2에서는 품질이 모두 만점이라 품질 하락을 감지할 수 없었다. R3부터 품질 판정을 새로 설계했다.

한 번의 실행이 거치는 과정

  1. 1

    조건 준비

    conditions/<id>/의 CLAUDE.md를 실행 폴더에 복사하고, hook은 --settings로 넘긴다.

  2. 2

    격리 실행

    실험 폴더 밖 새 세션에서 깨끗한 픽스처 복사본으로 실행한다. 사용자 설정은 빼고, 실행 순서는 --seed로 섞는다.

  3. 3

    토큰 측정

    stream-json 결과의 outputTokens와 thinkingTokens를 읽는다. 보이는 출력은 둘의 차이다.

  4. 4

    자동 채점

    숨은 테스트와 속성 테스트(Q1), 보고와 실제 결과 대조(Q3), 미끼 코드 15개로 변경 최소성(Q5)을 잰다.

  5. 5

    보고 충분성

    조건 정보를 받지 않은 세션이 최종 보고만 읽고 사실 질문에 답한다. 답을 정답과 대조한다(Q4).

  6. 6

    분석

    같은 문제끼리 짝지어 비율의 기하평균을 내고, 부트스트랩 CI와 비열등성 검정으로 판정한다.

운영 규칙

재현성과 비용 관리

  • 모든 세션 --model claude-opus-5-5 --effort high. 별칭과 fallback은 쓰지 않는다. 다른 모델이 기록되면 버린다.
  • 베이스라인은 같은 날 함께 실행한다. 모델 업데이트 영향을 막기 위해서다.
  • 5시간 한도 사용률이 85%를 넘으면 새 실행을 시작하지 않는다. 다시 실행하면 이어서 돈다.
  • 라운드마다 결과 파일과 실행 폴더를 분리한다(TD_OUT, TD_ROUND).

실험 결과

대부분은 "간결하게" 한 줄을 넘지 못했다

점은 베이스라인 대비 출력 토큰 변화의 추정치, 선은 95% 신뢰구간이다. 회색 띠(0 ~ −10%)는 채택 하한에 못 미치는 구간이고, 파란 세로선은 그 라운드의 P2 위치다. 행에 마우스를 올리거나 Tab으로 이동하면 thinking과 P2 대비 수치가 보인다.

1단계 → 2단계: 새 문제로 다시 쟀을 때

빈 원 = 1단계(문제 12개), 채운 원 = 2단계(새 문제 24개)

H05 계열(n09, r20, H05)은 새 문제에서 효과가 커졌다. r11 강조형은 1단계에서 P2보다 6% 앞섰지만 2단계에서는 차이가 0%가 됐다. 1단계의 작은 우위는 문제 12개의 우연일 수 있다.

도출한 결론

"덜 하게" 만드는 지시가 효과가 있었다. 출력 형태를 바꾸는 지시는 효과가 없었다

  1. 일반적인 간결 지시 한 줄이 출력 토큰을 약 25% 줄인다

    P2는 모든 라운드에서 −24 ~ −27%였고 품질 변화가 없었다. 문구 길이, 언어, 강조 정도에 둔감하다. 가설 대부분은 이 선을 넘지 못했으므로, 앞으로 새 개입은 베이스라인이 아니라 P2와 비교해야 한다.

  2. P2에 만족화·재검증 금지를 더하면 −40%까지 간다

    n09는 P2보다 17% 더 줄였고 thinking을 절반으로 줄였다. 새 문제 24개에서 정확도, 거짓 성공, 변경 최소성, 보고 충분성 모두 하락이 없었다.

  3. 비용의 핵심은 턴 수다

    턴마다 thinking과 해설이 붙는다. 델타 인코딩(H01)과 스크립트 파일화(H02)는 인자를 줄였지만 턴을 30~40% 늘려 출력이 오히려 늘었다. cp 후 Edit, sed 위임, 짧은 명령, 표 형식, 한 번에 쓰기도 모두 효과가 없었다. 도구 사용 방식을 강제하는 개입은 다섯 번 시도해 모두 실패했다.

  4. thinking은 간접적으로만 줄일 수 있다

    형식을 지정하면 API가 거부한다. 대신 "첫 해법을 채택하라", "출력은 비용이다"처럼 일의 양을 줄이는 지시가 thinking을 36~51% 줄였다.

  5. 보고 형식만 바꾸는 가설은 효과가 작다

    전보체, SOAP, 예측 오류만 보고, 참조형 보고는 −5 ~ +5%였다. 응답 텍스트는 원래 출력의 5% 정도다. 강조형 문구(r21)는 보고를 빈약하게 만들 위험이 있었다.

  6. 위약, 분해, 2단계 검증이 실제로 결론을 바꿨다

    위약이 없던 R1에서는 5개를 "채택"했지만 R2에서 모두 다시 판정했다. 분해 조건이 없었다면 H10을 "hook의 효과"로 잘못 기록했을 것이다. 2단계 검증에서 r11의 우위가 사라졌고 r21의 보고 문제가 드러났다.

아쉬운 점

"품질 하락 없음"이 증명한 범위는 좁다

측정한 범위 안에서는 하락이 없었다. 하지만 측정 장치가 하락을 잡아낼 여지 자체가 작았다.

정확도 천장 효과

난이도 보정 파일럿까지 포함해 모든 조건의 정확도가 만점이었다. 24개 중 0개 하락이면 하락 확률의 95% 상한은 약 12.5%다(rule of three). "하락 없음"이 아니라 "12.5% 이상 하락하지는 않음"까지만 말할 수 있다.

→ 2차: 베이스라인 점수 0.5~0.8 태스크

명세가 분명한 태스크만 썼다

세 생성기 모두 정답 해석이 하나다. "첫 해법 채택"이 가장 위험해지는 상황, 즉 요구사항을 해석해야 하는 일은 재지 않았다.

→ 2차 트랙 A

실사용보다 작은 태스크

실행당 출력은 2천~8천 토큰이었다. 실사용 로그는 파일 전체 쓰기가 보이는 출력의 60%였는데, 그런 규모에서는 결과가 다를 수 있다.

→ 2차 트랙 B, C

모델 하나, effort 하나

규칙상 Opus 5.5 high만 썼다. 다른 모델이나 effort에서 같은 지시가 같은 효과를 내는지는 모른다.

→ 규칙 변경 후 별도 라운드

R3·R4에는 위약(P1)이 없었다

"모든 라운드에 대조군 두 개"라는 규칙과 달리 R3·R4는 베이스라인과 P2만 넣었다. R2에서 P1이 +6%였고 P2 대비로 판정했으므로 결론은 같지만, 규칙 위반으로 기록해 둔다.

→ 2차: 모든 단계에 P1 복귀

Q4 채점기를 검수하지 않았다

quality.md에 계획한 사람 검수 30개(Cohen's κ ≥ 0.7)는 기록이 없다. tariff 생성기는 Q4 질문이 없어 빠졌고, rules 생성기에는 marginal + gt 조합의 정답 버그가 있다(모든 조건에 똑같이 적용).

→ 2차 0단계에서 보완

문제당 1회 실행

R3·R4는 조건 × 문제당 한 번씩만 실행했다. 문제 수로 보완했지만 같은 문제 안의 변동은 보지 못했다. 1단계 12개는 우위가 사라질 만큼 작았다(r11).

→ 2단계 검증은 유지

출력이 준 만큼 비용이 줄지는 않는다

R2의 P2는 출력 −25%, 총비용 −13%였다. 입력과 캐시 비용은 그대로이기 때문이다. 절감액을 말할 때는 총비용 기준으로 따로 보고해야 한다.

→ 2차: 총비용을 보조 판정에 포함
2차 실험 계획

유의미한 가설을 1차가 재지 못한 조건에서 다시 확인한다

1차의 결론은 "명세가 분명하고 작은 태스크"에서 얻은 것이다. 2차는 n09와 H05 계열이 그 밖에서도 품질을 해치지 않는지 확인한다. 핵심 질문은 하나다. 첫 해법을 채택하라는 지시가 해석이 필요한 일에서 품질을 떨어뜨리는가? 아래 내용은 제안이며 비용은 추정이다.
